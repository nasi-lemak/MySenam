# Configuration

Authoritative list of environment variables. `tests/docs.test.ts` checks that every variable the code reads is listed here and that every listed variable is read somewhere.

Everything is an environment variable; there is nothing else to configure.

| Variable | Default | What it does |
| -------- | ------- | ------------ |
| `MYSENAM_MARKETPLACE` | — | `on` for the shared marketplace: venues apply to join, are invoiced monthly, and stored credit is per venue |
| `MYSENAM_CREDIT_SCOPE` | `platform`, or `venue` on a marketplace | Whose stored credit is — see [whose credit it is](../features/payments-and-credit.md#whose-credit-it-is) |
| `SENTRY_DSN` | — | Also send each error to Sentry or GlitchTip (`https://key@host/project`); the dashboard's list works without it |
| `MYSENAM_ALERT_WEBHOOK` | — | A Slack, Discord or Google Chat incoming-webhook URL; alerts are posted there as `{"text": ...}` as well as emailed to the platform owners |
| `MYSENAM_VENUE_FEE` | `0` | On a marketplace, what a venue pays a month unless it has its own fee, or the owner has set tiers by size (see *Plans by size*) |
| `MYSENAM_FREE_MONTHS` | `1` | Free months from going live before a venue's first invoice |
| `MYSENAM_WHATSAPP_PACK` | `200` | On a marketplace, WhatsApp messages in a prepaid pack — see *What WhatsApp costs, and who pays* |
| `MYSENAM_WHATSAPP_PACK_PRICE` | `20` | RM for a pack, paid before any of it is sent |
| `MYSENAM_TAX_RATE`, `MYSENAM_TAX_REG_NO` | — | The platform operator's own SST or GST, once registered: the rate (%) added to venues' invoices and the registration number printed on them. Both, or no tax. See *Tax* |
| `MYSENAM_TAX_NAME` | the country's (`SST`, `GST`) | What the operator's tax is called on invoices |
| `MYSENAM_PAYMENT_PROVIDERS` | the country's usual one | The payment gateways venues may connect, comma-separated — see *Payment gateways* |
| `MYSENAM_PAYMENT_PROVIDER` | the first of those | The gateway the platform's own account is at, for venues paying invoices and WhatsApp packs online |
| `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` | — | The platform's own Stripe account, when `MYSENAM_PAYMENT_PROVIDER=stripe` |
| `BILLPLZ_API_KEY`, `BILLPLZ_COLLECTION_ID`, `BILLPLZ_X_SIGNATURE_KEY`, `BILLPLZ_SANDBOX` | — | The platform's own Billplz account, for venues paying their invoices online. `BILLPLZ_SANDBOX=on` for test payments |
| `OPERATOR_NAME`, `OPERATOR_REG_NO`, `OPERATOR_ADDRESS`, `OPERATOR_EMAIL` | — | Who runs the site, for the terms at `/terms`; name, address and email are also the contact in the privacy notice at `/privacy` |
| `MYSENAM_GEOCODER` | OpenStreetMap's Nominatim | Where venue addresses are looked up: a Nominatim URL of your own, or `off` |
| `MYSENAM_AUTO_APPROVE_BRANCHES` | — | `on` to approve a business's new branch without the platform owner, when its location checks pass |
| `MYSENAM_TRUST_FORWARDED_HOST` | — | `on` only behind a proxy that rewrites Host: read the storefront domain from `X-Forwarded-Host` |
| `MYSENAM_COUNTRY` | `MY` | The country this install serves, `MY` or `SG` — currency, phone numbers, time zone, languages, map, default gateway and the laws the terms cite. See *Countries* |
| `MYSENAM_STAFF_2FA` | `managers` on a production marketplace, else — | Make two-factor sign-in compulsory for staff: `owners` (platform owners), `managers` (owners and managers, not front desk) or `all`. On a production marketplace (`MYSENAM_MARKETPLACE=on`, `NODE_ENV=production`) the platform owner, business managers and venue managers are required **by default**, `all` stays `all`, `owners` is raised to `managers`, and **`off` (or a typo) is refused**: it does not switch it off, the start-up log says so and the owners are alerted. Elsewhere (development, tests, one venue's own install) it is as set; unset, each account chooses. See [two-factor sign-in](../architecture/authentication.md#two-factor-sign-in) and [ADR 0064](../architecture/decisions/0064-credentials-follow-their-owners-two-factor-by-default-and-counted-attempts.md) |
| `MYSENAM_SYNTHETIC_DATA` | — | `on` says this install holds synthetic data and no real account (staging, the acceptance server). Only then is `MYSENAM_STAFF_2FA=off` honoured on a production marketplace, and it is flagged by an alert all the same. Never set it on an install with real venues or customers |
| `SITE_NAME` | `MySenam` | What the site calls itself — the header, page titles, privacy notice, shared links |
| `ADMIN_EMAIL` | `admin@mysenam.my` | The first platform owner, created on a fresh database |
| `ADMIN_PASSWORD` | `mysenam-admin` (development only) | **Required in production**: at least 12 characters and not the default, or no owner account is made and the default is refused at sign-in ([admin access](../architecture/authentication.md#admin-access)) |
| `DATABASE_URL` | PGlite in `data/pglite` | `postgres://user:password@host:5432/db` in production. `pglite:/some/folder` or `pglite:memory` for PGlite |
| `DATABASE_POOL_SIZE` | `10` | Connections the app keeps open to the server |
| `MYSENAM_DATA_DIR` | `data/` | The app's own folder: backups, and `secret.key` when `MYSENAM_SECRET` is not set. Put it on a disk that survives a redeploy |
| `MYSENAM_BACKUP_DIR` | `backups/` in the data folder | Where snapshots are written |
| `MYSENAM_BACKUP_KEEP` | `14` | How many snapshots to keep before the oldest are retired |
| `MYSENAM_BACKUP_HOUR` | `3` | The hour, in the install country's time, of the nightly backup |
| `MYSENAM_BACKUP_RPO_HOURS` | `26` | The recovery-point target: owners are alerted when the newest copy that would survive losing the server is older ([backups](../operations/backups.md#backup-health)) |
| `CLAIMS_ARCHIVE_AFTER_DAYS` | `0` (off) | Move court time that ended more than this many days ago, held by something finished or cancelled, out of `claims` into `claims_archive`, in bounded batches from the scheduler. A whole number of days, 30 at the least (a smaller one is raised to 30; anything that is not a whole number switches it off); 90 is a good value once a venue's data is large. Nothing a venue or customer sees changes ([archiving past claims](../architecture/database.md#archiving-past-claims)) |
| `MYSENAM_CLAMD` | — | Where clamd (ClamAV's daemon) listens, `host:port` (port 3310 if left out), e.g. `127.0.0.1:3310`: supporting documents are scanned by it before anybody can open them. Unset or unreadable (and no `MYSENAM_CLAMD_ONDEMAND`), documents are still taken, into quarantine, and wait there unopened until a scanner is configured and passes them ([the malware scanner](../operations/deployment.md#the-malware-scanner)). The acceptance scenarios set it themselves, to a stand-in on the loopback that is not ClamAV (`tests/uat/scanner.ts`; [testing](testing.md#visual-acceptance-scenarios)), unless it is already set |
| `MYSENAM_CLAMD_ONDEMAND` | — | The path of a clamd.conf (the kit's: `/etc/mysenam/clamd-ondemand.conf`): the app then starts clamd itself, as its own user, while documents wait and no scanner answers, and stops it when idle ([choosing a mode](../operations/deployment.md#choosing-how-clamd-runs)). The file must set `TCPSocket` and a loopback `TCPAddr`; without `MYSENAM_CLAMD` the app reaches clamd there. Unusable, it is reported at start-up and on the owner's panel, and documents wait |
| `MYSENAM_CLAMD_BINARY` | `/usr/sbin/clamd` | The clamd the on-demand scanner starts, as `<binary> -F --config-file=<MYSENAM_CLAMD_ONDEMAND>` |
| `MYSENAM_CLAMD_IDLE_MINUTES` | `5` | The on-demand clamd is stopped after this many minutes with nothing waiting (1–1440) |
| `MYSENAM_CLAMD_START_SECONDS` | `120` | The on-demand clamd must answer within this many seconds of starting, or it is stopped and tried again after a pause (10–3600) |
| `MYSENAM_CLAMD_MIN_MEMORY_MB` | `1200` | The on-demand clamd is started only while the machine's `MemAvailable` is above this many MiB (and freshclam is not running); otherwise documents wait, and the owners are told after 30 minutes |
| `MYSENAM_DOCUMENT_SCAN` | — | **Withdrawn** (27 October 2026): `off` once took documents unscanned. It is ignored, and a start-up warning asks for it to be removed: no document is released without a scan ([security](../architecture/security.md#malware-scanning)) |
| `MYSENAM_SCHEDULER` | on in production | `off` to leave nightly backups, message sending and the rest of the scheduled work to your own cron. Not needed for several instances, which share the work by a lease |
| `MYSENAM_LONG_JOB_MINUTES` | `120` | The longest the scheduler waits for the backup and its off-site copy, which run apart from the rest of the scheduled work on a lease of their own ([overview](../architecture/overview.md#more-than-one-instance)). Past it the lease is let go, so another instance may take the work, and the owners are told |
| `MYSENAM_RATE_LIMITS` | `memory` | `shared` to keep rate-limit counters in Postgres, for more than one instance |
| `MYINVOIS_CLIENT_ID`, `MYINVOIS_CLIENT_SECRET` | unset | The platform's own MyInvois ERP client, to act as venues' intermediary for LHDN e-invoicing (Malaysia) |
| `ACCOUNTING_PUSH_APPROVED` | unset | `yes` once sending venues' sales to an accounting package (Xero, which keeps them outside the country) has been approved and recorded. Until then no venue is offered the connection and nothing is sent, whatever else is set ([Xero](../integrations/xero.md#the-install-switch-and-the-xero-app), [privacy](../architecture/privacy.md#live-accounting-push)) |
| `XERO_CLIENT_ID`, `XERO_CLIENT_SECRET`, `XERO_REDIRECT_URI` | unset | The install's own Xero app (developer.xero.com): the redirect address is `<site>/api/admin/accounting/xero/callback`. The secret belongs in the secret store. A venue's manager connects the venue's own organisation through it |
| `XERO_SCOPES` | `offline_access accounting.invoices accounting.payments accounting.contacts accounting.settings.read` | What the app asks Xero for, where the Xero app was made with different scopes (an older one may hold `accounting.transactions`) |
| `OFFSITE_S3_*` | — | Where to copy each backup off the machine (Backblaze B2 preferred, Amazon S3 supported); see *Off-site copies*. `OFFSITE_S3_REGION` is read from a B2 or S3 endpoint when not set |
| `OFFSITE_S3_READ_ACCESS_KEY_ID` / `OFFSITE_S3_READ_SECRET_ACCESS_KEY` | — | The read key, on the machine you restore from only ([backups](../operations/backups.md#keys-and-object-lock)) |
| `MESSAGE_RETENTION_DAYS` | `90` | Days a conversation between players is kept after its game, team, group or fixture ended (7 to 730); then it is deleted with its messages ([privacy](../architecture/privacy.md#messages-between-players)) |
| `MESSAGE_REPORT_RETENTION_DAYS` | `365` | Days a report of a message, with the copy of the conversation frozen with it, is kept after it was dealt with (30 to 1095); an open one is kept until it is |
| `YOUTH_MESSAGE_RETENTION_DAYS` | `60` | Days a [supervised youth group's](../features/player-messages.md#supervised-youth-groups) conversation is kept after the group ended (7 to 365): shorter than an adults' conversation; then it is deleted with its messages |
| `YOUTH_REMOVED_RETENTION_DAYS` | `30` | Days the words of a message a supervisor removed from a youth group's thread are kept (for staff review) before they are deleted (7 to 365); the message stays as *removed* |
| `YOUTH_MESSAGING_LAUNCH_APPROVED` | unset | **Youth messaging is off in production unless this is `yes`** (on in development and tests). Off: no group can be marked a youth group, a minor has no seat anywhere, no youth thread is read or written, guardians and staff are told plainly that it is not enabled, adults' messaging is unaffected, and what is stored is shown nowhere except to safeguarding administrators for an open case. Setting it is the owner's deliberate decision, after the [launch gate](../operations/legal-review-youth-messaging.md#launch-gate) is met; [ADR 0052](../architecture/decisions/0052-youth-messaging-interim-safeguards-pending-legal-review.md) |

| `YOUTH_PROTECTIVE_REVIEW_DAYS` | `7` | Days a protective restriction on a reported adult may stand before it must be reviewed (1 to 90); past it unreviewed it is told to the platform's owners, and repeated at this interval; it is never lifted or converted by itself. **Operational, not a legal period** |
| `SAFEGUARDING_EVIDENCE_RETENTION_DAYS` | unset | Days after which a **closed** youth case's evidence copy and case actions are deleted (30 or more). **Unset: nothing of the kind is ever deleted automatically.** Setting it **requires legal approval first**; it never touches a case that is open, has a restriction in force or is under a legal hold, nor the audit records ([privacy](../architecture/privacy.md#youth-messaging-evidence)) |
| `SAFEGUARDING_REVIEW_MONTHS` | `12` | Months a closed case or a legal hold may be kept before the platform's owners are asked, by a safeguarding email and a needs-attention line, to decide whether to keep it (1 to 120): a prompt for a decision, never a deletion. Operational |
| `YOUTH_QUIET_HOURS` | `22:00-07:00` | The hours in which a minor's seat in a youth group cannot write, as `HH:MM-HH:MM`, read in the group's venue's time zone (the install's for a group with no venue); `off` turns it off for the whole install. | `MESSAGE_DIGEST_HOURS` | `6` | Hours in the digest of unread messages between players: at most one email per person per conversation per period, sent by the scheduler once the period is over, if still unread; a whole number from 1 to 24 ([messages](../features/player-messages.md#telling-people-a-digest-never-the-message)) |
| `OFFSITE_DATA_LOCATION` | — | Country the bucket keeps data in; nothing is copied off-site until it is set, or while it disagrees with the country a B2 or S3 endpoint names ([backups](../operations/backups.md#where-the-data-may-go)) |

Set by the platform rather than by you, and read by the code: `NODE_ENV` (production checks and the scheduler), `NEXT_RUNTIME` (server instrumentation), `HOSTNAME` (names this instance in the scheduler lease). The test suite also reads `TEST_DATABASE_URL`, and `MYSENAM_TEST_CLAMD` (`host:port` of a clamd for the real-engine test, which otherwise starts its own where `clamd` is installed, or is skipped); the verification runner (`scripts/verify.mjs`) reads `TEST_DATABASE_URL` and `DATABASE_URL` (it refuses a server that is the second) and `NODE_OPTIONS` (it adds `--max-old-space-size=4096` for every step unless one is set); the browser tests, the acceptance scenarios and the staging tools read `E2E_URL`, `E2E_OWNER_EMAIL`, `E2E_OWNER_PASSWORD`, `SEED_DATABASE_URL` and `UAT_*`, and pass on the machine's own `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY` and `NODE_EXTRA_CA_CERTS` when building an image; see [testing](testing.md).

Read only by the operator's tools, never by the app, and set in the shell or the execution environment's secret store, never in a production `.env`: remote staging (`scripts/stage-remote.mjs`) reads `DIGITALOCEAN_TOKEN`, `STAGING_IMAGE`, `STAGING_REGISTRY_AUTH` and `STAGING_MAX_USD`, and its tests point it elsewhere with `DO_API_URL`, `STAGING_URL_TEMPLATE`, `STAGING_POLL_MS` and `STAGING_WAIT_MS`; the real-service checks (`scripts/verify-integrations.mjs`) read `STRIPE_TEST_SECRET_KEY`, `STRIPE_TEST_WEBHOOK_SECRET`, `STRIPE_TEST_CURRENCY`, `BILLPLZ_SANDBOX_API_KEY`, `BILLPLZ_SANDBOX_COLLECTION_ID`, `BILLPLZ_SANDBOX_X_SIGNATURE_KEY`, `DKIM_SELECTOR`, `VERIFY_EMAIL_TO`, `VERIFY_WHATSAPP_TO`, `VERIFY_WHATSAPP_TEMPLATE`, `VERIFY_SMS_TO` and `CHROMIUM_PATH`, and their tests use `STRIPE_API_URL`, `BILLPLZ_SANDBOX_URL`, `WHATSAPP_GRAPH_URL` and `TWILIO_API_URL`; the Xero check (`scripts/verify-xero.mjs`, against a Xero demo company) reads `XERO_VERIFY_TOKEN_FILE`, `XERO_VERIFY_REFRESH_TOKEN`, `XERO_VERIFY_DEMO_COMPANY_ONLY`, `XERO_VERIFY_CODE` and `XERO_VERIFY_REPORT_DIR` ([Xero](../integrations/xero.md#verifying-against-a-demo-company)). `XERO_API_URL` and `XERO_IDENTITY_URL` point the Xero adapter at a stand-in in tests and are never set on a real install. See [testing](testing.md#staging-and-real-services).

`.env.example` names every variable in this table, commented out and grouped, with a line on each; copy it to `.env.local`. This table is the authoritative list, and `tests/docs.test.ts` checks the two agree.

On a production start the server warns about an unset, default or short
`ADMIN_PASSWORD`, an unset `ADMIN_EMAIL`, and missing off-site backup settings
(`src/instrumentation-node.ts`). It still starts, because a venue in the middle
of a Saturday does not want its booking system declining to boot; but the
default password then opens nothing.
